# 结构化内容摘要

## Agent 是系统能力，不只是模型能力

对谈把可用 Agent 描述为模型、上下文、检索、工具、历史信息和编排机制的组合。提升 Agent 的实用性，不只依赖基础模型变强，也可以通过实际任务暴露失败点，再把人类有效的方法写成指引或 skill，让模型按可复用流程调用工具。

Jeff Dean 以底层性能优化为例，介绍了一个把微基准、修改代码、复测、扩大基准范围和检查 cache footprint 串成循环的 skill。文章还提到，长链路 Agent 容易在偏离训练分布后持续恶化；可用更清晰的 skill 约束路径，或让多个 Agent 搜索不同解法，再由评估器筛选。

## 规格与评估决定长任务能否闭环

对谈认为，Agent 获得的规格越清楚，越不需要猜测用户意图。把软件从一种语言迁移到另一种语言之所以相对适合 Agent，是因为原实现和测试共同提供了高密度规格与行为对照。

在自动实验场景中，候选生成不是唯一瓶颈。若评价一次候选仍需很长时间，实验循环就无法高频运转；可以考虑学习一个更快的近似评估器，但必须处理近似误差与适用范围。对谈把这一逻辑扩展到机器学习、科学和工程的自动化发现。

## AI 产品切入口需要考虑通用模型的进步速度

对谈提出一个方向筛选启发：如果通用模型已经能完成任务的一部分，能力可能很快继续增长；若模型几乎完全失败，小团队反而可能有切入口。文章同时给出两类更具体的优势来源：通用模型无权访问的私有或个人数据，以及针对窄领域训练、准确率更高的专用模型。

这不是经验证的普遍商业定律。模型当前成功率很低，也可能意味着需求弱、问题不可解、数据不足或评估方法有误；模型已有部分能力，也不排除团队通过工作流、交互、合规、集成、服务或分发建立价值。

## 系统与硬件约束

对谈强调推理延迟、数据搬运、内存层级、互连带宽和能耗对 AI 系统上层设计的影响，并认为低功耗、低延迟的专用推理硬件仍有较大空间。其方法论不是记住单个数字，而是先做数量级估算，识别真正瓶颈，再质疑当前解法的默认假设。

## 人的角色：选问题、写清规格、建立品味

当执行能力因 Agent 而变便宜，人的稀缺价值更集中在决定做什么、判断什么重要、写出清晰规格以及选择合作者。文章给出的练习是记录未来十二个月可能重要的问题，届时逐项复盘实际进展，以积累对问题选择的反馈样本。

# 入库决策

1. CREATE：Agent 长任务的可靠性依赖规格、skills、工具和评估反馈形成闭环，而不是仅依赖更强模型或更长运行时间。
2. CREATE：AI 产品切入口要同时检验当前模型能力、能力进步速度和可持续差异化资产，不能把暂时的能力缺口直接当作护城河。
3. CREATE：自动化实验的扩展上限常由评估器的速度与可信度决定，生成更多候选并不自动带来更多有效发现。
4. CREATE：AI 系统优化应优先核算数据搬运、内存层级与低延迟约束，不能只看 FLOPs 或参数量。
