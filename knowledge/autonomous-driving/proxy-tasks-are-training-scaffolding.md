# 当前结论

当物理 AI 需要从高维、长时序感知输入直接预测少量控制量时，主任务监督可能严重欠约束。与任务机制相关的几何、检测、分割、深度、光流、OCR 或未来预测等代理任务，可以作为训练脚手架增加监督密度、约束中间表征；但它们不是最终产品目标，也不能自动证明模型获得了因果性、可解释性或安全性。

# 判断依据

来源把端到端驾驶描述为极高维视频输入到转向和加减速等低维输出的映射。大量不同视觉场景可能对应相似动作，仅靠动作误差回传时，模型可能利用道路背景、亮度或数据分布等捷径，而没有学习对驾驶真正必要的状态。

代理任务为像素、目标、几何和时间关系提供更稠密的训练信号，也迫使共享编码器同时支持多种可读表征。知识库接受它们作为改善表征与优化条件的合理方法，但不接受来源中“把因果注入模型”的强说法：多任务相关性仍可能是伪相关，只有干预、反事实、分布外和闭环行为证据才能进一步支持因果主张。

来源还主张代理指标只需保持“健康”，最终应评价驾驶任务。知识库将其改写为：代理指标是训练诊断与退化预警，不能凌驾于主任务；主任务也不能只看平均驾驶表现，仍需安全、长尾、舒适、规则遵从和故障边界等分解指标。

本次只核对了二手公众号文章的正文一致性，没有对照 Tesla 演讲、PPT、代码、论文或独立道路数据，因此置信度为 low。

# 应用方式

设计端到端物理 AI 训练时，可按以下顺序使用代理任务：

1. 先识别主任务最欠约束的能力，例如几何、动态目标、可读标志、遮挡或未来演化；
2. 选择与这些能力直接相关、标签或自监督信号可获得的代理任务；
3. 记录每个任务的监督来源、噪声、覆盖和与主任务的预期机制；
4. 用 loss 平衡、梯度冲突监控和消融实验检查是否发生负迁移；
5. 同时观察代理指标、离线主任务、仿真闭环和受控实车指标，不用单一 benchmark 宣布成功；
6. 部署前单独验证分布外、传感器退化、极端天气、异常交通参与者和安全失败模式。

# 适用边界

- 代理任务选择错误、标签带偏或 loss 权重失衡，可能损害主任务并增加训练复杂度。
- 中间表征可读，不等于模型决策链条可解释；部署时不输出代理头，也会降低在线可观测性。
- 主任务闭环指标是产品目标，不意味着可以忽略检测、占用或规则等诊断指标。
- 模仿学习、多任务学习、世界模型、规划约束和模块化安全层可以组合使用，不应被二分为“端到端”与“旧方法”。
- 是否保留运行时安全监控应由风险分析、验证覆盖、系统架构和法规决定，不能从单一公司说法推出通用结论。

# 不同观点与冲突

一种观点认为，只要基础模型、自监督预训练和数据规模足够，显式代理任务会限制表征或增加人工偏见；另一种观点认为高风险系统需要更强的结构化中间任务和显式约束。当前没有足够证据选择单一答案，更可行的做法是按失败模式进行消融，并把闭环安全表现作为共同验收层。
